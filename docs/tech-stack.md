# Tech stack

Single full-stack TypeScript app in one package (no separate frontend and backend projects).

- **Project layout:** scaffolded with the official template (`npx create-react-router@latest`) in the repo root, next to `docs/` and `AGENTS.md`, with no wrapper folder. The other tools are added on top of it one at a time.
- **Framework:** React Router (framework mode), not Next.js
- **Language:** TypeScript
- **Validation:** Zod schemas parse the submitted `FormData` in React Router actions and infer the TypeScript types. Validation errors are returned to the form as field-level messages.
- **Environment config:** a gitignored `.env` file holds `DATABASE_URL`. A committed `.env.example` has the same keys with safe local defaults, and the Docker Compose Postgres service uses the same defaults. A small Zod-validated module reads the variables and fails at startup if one is missing.
- **AI tooling files:** the shared config is committed (`.mcp.json`, `skills-lock.json`, `.agents/`, and anything shared in `.claude/`) so everyone who clones the repo gets the same setup. Per-machine files such as `.claude/settings.local.json` are listed in `.gitignore`.
- **npm scripts:**
    - `dev`: start the dev server
    - `build` and `start`: build and run the production build
    - `typecheck`: run `tsc`
    - `lint`: run oxlint
    - `lint:design`: lint `DESIGN.md` with `@google/design.md`
    - `format`: run oxfmt
    - `test`: run Vitest
    - `test:e2e`: run Playwright
    - `db:generate`, `db:migrate` and `db:seed`: the Drizzle migration commands and the seed script
    - `db:up`: run `docker compose up -d`
- **Styling:** Tailwind CSS, with no component library
- **Drag and drop:** `@dnd-kit/core`
- **Unit tests:** Vitest, for `app/**/*.test.{ts,tsx}`. The run passes while there are no tests yet.
- **E2E tests:** Playwright, set up from the start. Tests live in `e2e/`. Run `npx playwright install chromium` once to download the browser. The dev server is started automatically.
- **Linting:** oxlint (not ESLint)
- **Formatting:** oxfmt (not Prettier), with 4-space indentation. `.oxfmtrc.json` skips generated and vendored files (`drizzle/`, lock files, `.mcp.json`, `.agents/`, `.claude/`) and `package.json`, which npm rewrites.
- **Design system file:** `DESIGN.md` in the repo root, in the [Google design.md](https://github.com/google-labs-code/design.md) format. It is linted with `@google/design.md` (dev dependency, `npm run lint:design`). Always read it before making UI changes (also stated in `AGENTS.md`). Errors (broken token references, invalid colors) fail the command; warnings do not. The pre-commit hook runs it only when `DESIGN.md` is staged.
- **Tailwind theme from DESIGN.md:** the theme tokens (colors, fonts, text sizes, radii, spacing) are generated from `DESIGN.md`, not written by hand. `npm run design:tokens` runs `design.md export --format css-tailwind` into `app/design-tokens.generated.css`, which `app/app.css` imports. The generated file is committed and never edited by hand. It is regenerated by `npm run dev` (via `predev`) and by the pre-commit hook when `DESIGN.md` is staged. It is skipped by oxfmt. Hand-written theme additions that are not in `DESIGN.md` go in the `@theme` block of `app/app.css`.
- **Type checking:** `tsc`
- **Pre-commit hook:** Lefthook (config in `lefthook.yml`, installed by the `prepare` script on `npm install`). It formats the staged files with oxfmt and re-stages them, lints them with oxlint, lints `DESIGN.md` when it is staged, and runs `tsc`. Unit and E2E tests are not part of the hook.
- **CI:** none for now
- **Docker Compose (Postgres):**
    - Image `postgres:18`, pinned to the major version (not the `-alpine` variant)
    - A named volume keeps the data across `docker compose down`. `docker compose down -v` wipes it for a clean reset.
    - Port `5432` on the host
    - Throwaway local credentials: user, password and database all named `taskmanagement`, matching the defaults in `.env.example`
    - A `pg_isready` health check, so migrations and the seed script can wait for the database
- **Package manager:** npm, not pnpm
- **Node:** current LTS, pinned in `.nvmrc` and the `engines` field of `package.json`
- **Database:** PostgreSQL, run locally with Docker Compose (not SQLite)
- **ORM:** Drizzle, not Prisma
- **Postgres driver:** `postgres` (postgres.js), not `pg`
- **Drizzle layout:** the config is `drizzle.config.ts`, the schema is `app/db/schema.ts`, the client is `app/db/index.server.ts`, and generated migrations go to `drizzle/`. The schema holds `users` and `tasks` (see [mvp.md](mvp.md)).
- **Schema changes:** versioned migrations. Change the Drizzle schema, run `drizzle-kit generate`, commit the SQL migration file, and apply it with `drizzle-kit migrate`. Do not use `drizzle-kit push`.
- **Seed data:** a seed script fills the local database with a few users and tasks. `npm run db:seed` runs `app/db/seed.ts` with `tsx`.
